# Организатор на събития — от event.json до сайт с въпросници и прожекция

Шаблонът на Shinkansen за събития: интензиви, академии, демо дни. Едно събитие е папка: `event.json` (какво, кога,
темите, разписанието, въпросниците), `data/lektori.json` и `data/partnyori.json` (по един запис на човек)
и по желание `assets/` (лого, локални шрифтове за офлайн).
От тях организаторът проверява, казва какво още липсва и сглобява готов сайт.

**Истинските събития не са в репото.** Тук са моделът и един измислен пример (`examples/intensive`).
Събитието на живо си има своя папка извън репото и се допълва в движение.

**Части:**
- `organizer.py` — `new` · `check` · `build`, само стандартна библиотека на Python 3
- `examples/intensive/` — измислен тридневен интензив: 3 теми, лаборатория в 4 роли, 2 въпросника
- `event.schema.md` — всички ключове
- `assets/` — стил, прожекция (`present.js`), лектори в движение (`people.js`), въпросници (`forms.js`)
- `php/` — приемане на отговорите (`submit.php`), износ в CSV (`export.php`), `config.sample.php`
- `ops.py` — `fill`, `package`, `qa`, `demo-import`, `feedback`; `deploy.py` — качването в cPanel
- `tests/` — проверка, сглобяване, екраниране, целият път запис → износ през PHP (SQLite вместо MySQL), пакет, qa, fill, deploy с подставен cPanel

## Как се пуска

```bash
python3 apps/organizer/organizer.py new ~/sabitiya/moe-sabitie      # копие на примера, извън репото
python3 apps/organizer/organizer.py check ~/sabitiya/moe-sabitie    # грешки и „какво още липсва“
python3 apps/organizer/organizer.py build ~/sabitiya/moe-sabitie ~/sabitiya/moe-sabitie/_site
python3 apps/organizer/organizer.py build ПАПКА ИЗХОД --demo        # без PHP и без изпращане (преглед)
```

`check` различава **грешки** (спират сглобяването: тема, която я няма в разписанието, застъпени часове,
ден извън датите, непозната роля в лабораторията, лош цвят, ред на таблица с грешен брой клетки) и
**липси** (не спират: празна лаборатория, тема без „Демо на живо“, час без стойност, няма потвърден лектор,
събитието още е скрито). Изброява и всяко място с `[ЧАКА …]` — това е списъкът за доклада.

След сглобяването `build` проверява **вътрешните връзки** (0 счупени) и **забранените текстове**
(`publish.forbid_text` и `forbid_regex` — стари дати, „ООД“ без „Е“) във всеки файл и спира, ако намери.
Код на изход: 0 · 1 грешки · 2 аргументи.

Тестове:

```bash
cd apps/organizer && python3 -m unittest discover -s tests -v    # PHP частта се пропуска, ако няма php
php apps/organizer/php/tests/validate_test.php
```

## Какво се сглобява

| Файл | Какво е |
|---|---|
| `index.html` | начало: заглавие, три числа, за кого (ролите), свои раздели, темите, дните, записване |
| `programa.html` | всички теми като карти |
| `tema-01-<slug>.html` … | въпросът, понятията, свои раздели (карти, таблица), **демо на живо**, **лаборатория** (колона на роля), какво отнасяш вкъщи, изходник |
| `razpisanie.html` | дни и часове, почивки, връзки към темите |
| `lektori.html` · `organizatori.html` | профили от `data/*.json`; празните места са „очаква потвърждение“ |
| `privacy.html` | уведомлението за поверителност (от `privacy`) |
| `<slug>.html` | по един въпросник на всеки запис от `forms`, по желание на групи (А · Б · В) |
| `data/*.json` | лектори и партньори — четат се в движение от страницата |
| `api/` | `submit.php`, `lib.php`, `forms.json` (какво се приема); последните два са забранени отвън |
| `admin/export.php` | износ в CSV; работи само в папка, заключена с парола |
| `sql/schema.sql` | по таблица на въпросник, `_kontakt` за личните му полета, таблица за ограничението; пуска се от човек |
| `sql/config.sample.php` | шаблонът за config; `sql/` е забранена отвън |
| `.htaccess` | `noindex` докато не е „go“, без списък на папките |

### Прожекция

На всяка страница: **P** включва и изключва, стрелките, PageUp/PageDown и кликерът прелистват,
**F** е цял екран, **Esc** излиза. Всеки блок заема един екран, шрифтът е от 28 px нагоре (44 px на 1920×1080).
След последния блок продължава в следващата страница (начало → програма → темите → разписание), а назад —
в последния блок на предишната. Без мрежа и без библиотеки; за офлайн шрифтовете се слагат в `assets/` на
събитието и се връзват с `theme.stylesheets`. `#p3` в адреса отваря направо трети екран, `#pend` — последния.

### Лектори и партньори в движение

Човек се добавя с един запис в `data/lektori.json` (или `data/partnyori.json`) на сървъра, без ново сглобяване:

```json
{"name": "Име Фамилия", "role": "Тема 3", "bio": "Едно изречение.", "photo": "assets/hora/ime.jpg", "link": "https://…"}
```

Запис само със `slot` (`{"slot": "Памет и бази данни"}`) е празно място: „Лектор · Памет и бази данни —
очаква потвърждение“. Без измислени имена и снимки.

### Въпросниците

Полета: `single`, `multi` (с `max`), `text`, `textarea` (с `max_length`), `email`, `consent`
(`required_if`: става задължително, щом е попълнено име или имейл). `options_from: "topics"` взима
темите за опции; `other: true` добавя „Друго: …“.

Сървърът записва **само** полетата и опциите от `forms.json`, всеки въпросник в своя таблица; всичко
друго се отхвърля. **Личните полета** — имейл, съгласие и всяко поле с `"personal": true` (име, телефон) —
отиват в отделна таблица `<таблица>_kontakt`, свързана с отговора по номер. Така при искане за изтриване
се трие само редът с личните данни (`DELETE FROM … _kontakt WHERE response_id = N`), а отговорите остават
за статистика. Износът в CSV ги съединява обратно. `check` предупреждава за поле „Име“/„Телефон“ без `personal`. Скрито поле и минимум 3 секунди спират ботовете (отговарят „добре“, нищо не се записва).
Ограничение: до `server.rate_limit_per_hour` изпращания от адрес за час — пази се само HMAC на адреса и само
за този час. Без имейли, без бисквитки, без анализ на посещенията.
В CSV клетките, започващи с `=`, `+`, `-`, `@`, се обезвреждат за Excel.

## Как се води събитие от начало до край

За следващия човек или агент. Всяка стъпка е команда; нищо не отива на живо без `--go` от човек.

| # | Стъпка | Команда | Какво дава |
|---|---|---|---|
| 1 | Папка на събитието (извън репото) | `organizer.py new ПАПКА` | `event.json`, `data/`, `assets/`, `izvori/` от примера |
| 2 | Съдържание от бележките | `organizer.py fill ПАПКА --dry-run`, после без `--dry-run` | JSON блоковете от `sources` → `event.json`; разлика по ключове; старото → `event.json.orig_ДАТА`; ред в `decisions.md` |
| 3 | Какво липсва | `organizer.py check ПАПКА` | грешки, липси, всички `[ЧАКА …]` — списъкът за доклада |
| 4 | Демата | `organizer.py demo-import ПАПКА резултати.json --words думи.txt` | „Проба на …: минала · 5,7 s · до 60 °C“ под демото на всяка тема; бележките минават през филтъра |
| 5 | Сглобяване | `organizer.py build ПАПКА САЙТ` | сайтът; спира при счупена връзка или забранен текст |
| 6 | Проверка A5 | `organizer.py qa ПАПКА ОТЧЕТ` | `qa_report.md` + снимки 360/1440 px; въпросниците на живо (PHP + SQLite) |
| 7 | Пакет | `organizer.py package САЙТ ПАКЕТИ --prev ПРЕДИШЕН.tgz` | `.tgz`, `.sha256`, `.manifest.txt`, `.diff.txt` („сменен tema-12…“) |
| 8 | План за качване | `organizer.py deploy ПАКЕТ.tgz --config deploy.json` | само показва: връзка, `.htaccess`, какво ще се преименува и качи |
| 9 | Качване (след „go“) | `… deploy … --go --htaccess-ok` | A6: архив на старото, качване, маркер, проверка отвън, тестов отговор |
| 10 | Заключване | cPanel → Directory Privacy за `admin/` | веднага след т. 9 |
| 11 | Обратна връзка | `organizer.py feedback --url …/admin/export.php?form=ID --spec САЙТ/api/forms.json --out обобщение.md` | броене по отговор, свободните текстове; без личните полета |

**Какво е на човека:** решенията (записват се в бележките, от които `fill` чете), „go“, `sql/schema.sql` в
phpMyAdmin, config файлът с паролата над `public_html`, API токенът за cPanel (Manage API Tokens) във файл
извън репото, заключването на `admin/`.

**Договорът за резултатите от демата** (`demo-import`): JSON `[{"topic": 3, "status": "ok|fail|skip",
"seconds": 75.2, "date": "2026-09-27", "max_temp_c": 66, "note": "…"}]` (или `{"results": […]}`); ако го
няма — лог с редове като `t03 OK 75.2 s … 66 °C`. Потребители, машини, адреси, портове, пътища, PID и думите
от `--words` не стигат до страницата.

**deploy.json** (извън репото): `{"cpanel": "https://сървър:2083", "user": "…", "token_file": "~/…/cpanel.token",
"public_html": "public_html", "dir": "ai-start", "site_url": "https://домейн/ai-start/"}`. Първото истинско
`--go` — с човек до екрана: API-то на cPanel е изпитано само с подставен сървър.

## Качване на споделен хостинг (cPanel)

1. **Първо** се чете `.htaccess` в `public_html` — подпапката наследява правилата му (пренасочвания, кеш).
2. Човекът пуска `sql/schema.sql` в phpMyAdmin. Сайтът сам не създава таблици на живо.
3. `sql/config.sample.php` → копие **извън** `public_html`, на пътя от `server.config_file`. Паролата и
   `salt` се въвеждат там, на сървъра — никога в репото, в чата или в публичната папка.
4. Съдържанието на `ИЗХОД/` отива в подпапката на събитието, например `public_html/<адрес>/`.
5. `admin/` се заключва от cPanel → Directory Privacy. Без това износът отговаря 403.
6. Проверка отвън: всички страници 200, тестов отговор, CSV.
7. „go“: `publish.indexable: true` (и `publish.base_url` за sitemap.xml) → ново сглобяване → качване.

## Ниво

чернови — сглобява, проверява и пакетира в папки. `deploy` без `--go` само чете; с `--go` действа, но само след „go“ от човек и без да трие.
