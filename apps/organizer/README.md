# Организатор на събития — от event.json до сайт с въпросници и прожекция

Шаблонът на Shinkansen за събития: интензиви, академии, демо дни. Едно събитие се описва в два файла,
`event.json` (какво, кога, темите, разписанието, въпросниците) и `people.json` (лектори и партньори).
От тях организаторът проверява, казва какво още липсва и сглобява готов сайт.

**Истинските събития не са в репото.** Тук са моделът и един измислен пример (`examples/intensive`).
Събитието на живо си има своя папка извън репото и се допълва в движение.

**Части:**
- `organizer.py` — `new` · `check` · `build`, само стандартна библиотека на Python 3
- `examples/intensive/` — измислен тридневен интензив: 3 теми, лаборатория в 4 роли, 2 въпросника
- `assets/` — стил, прожекция (`present.js`), лектори в движение (`people.js`), въпросници (`forms.js`)
- `php/` — приемане на отговорите (`submit.php`), износ в CSV (`export.php`), `config.example.php`
- `tests/` — проверка, сглобяване, екраниране и целият път запис → износ през PHP (SQLite вместо MySQL)

## Как се пуска

```bash
python3 apps/organizer/organizer.py new ~/sabitiya/moe-sabitie      # копие на примера, извън репото
python3 apps/organizer/organizer.py check ~/sabitiya/moe-sabitie    # грешки и „какво още липсва“
python3 apps/organizer/organizer.py build ~/sabitiya/moe-sabitie ~/sabitiya/moe-sabitie/_site
python3 apps/organizer/organizer.py build ПАПКА ИЗХОД --demo        # без PHP и без изпращане (преглед)
```

`check` различава **грешки** (спират сглобяването: тема, която я няма в разписанието, застъпени часове,
ден извън датите, непозната роля в лабораторията, лош цвят) и **липси** (не спират: празна лаборатория,
тема без „Демо на живо“, няма лектори, събитието още е скрито). Код на изход: 0 · 1 грешки · 2 аргументи.

Тестове:

```bash
cd apps/organizer && python3 -m unittest discover -s tests -v    # PHP частта се пропуска, ако няма php
php apps/organizer/php/tests/validate_test.php
```

## Какво се сглобява

| Файл | Какво е |
|---|---|
| `index.html` | начало: заглавие, защо така, за кого (ролите), темите, дните, лектори, партньори, записване |
| `programa.html` | всички теми |
| `tema-01.html` … | тема: какво ще можеш, свои раздели, **лаборатория** (по колона на роля), **демо на живо** |
| `razpisanie.html` | програмата по дни и часове, с връзки към темите |
| `<slug>.html` | по един въпросник на всеки запис от `forms` |
| `people.json` | лектори и партньори — чете се в движение от страницата |
| `api/` | `submit.php`, `lib.php`, `forms.json` (какво се приема); последните два са забранени отвън |
| `export/index.php` | износ в CSV; работи само в папка, заключена с парола |
| `.htaccess` | `noindex` докато не е „go“, без списък на папките |

### Прожекция

На всяка страница: **P** включва и изключва, стрелките, PageUp/PageDown и кликерът прелистват,
**F** е цял екран, **Esc** излиза. Всеки блок заема един екран, шрифтът е от 28 px нагоре. Без мрежа и без
библиотеки: сайтът може да се отвори и от папката. `#p3` в адреса отваря направо трети екран.

### Лектори и партньори в движение

Човек се добавя с един ред в `people.json` на сървъра, без ново сглобяване:

```json
{"name": "Име Фамилия", "role": "Тема 2", "bio": "Едно изречение.", "photo": "img/ime.jpg", "link": "https://…"}
```

Докато няма хора, се показват празни профили („Предстои“) до `placeholders`.

### Въпросниците

Полета: `single`, `multi` (с `max`), `text`, `textarea` (с `max_length`), `email`, `consent`
(`required_if`: става задължително, щом е попълнено име или имейл). `options_from: "topics"` взима
темите за опции; `other: true` добавя „Друго: …“.

Сървърът записва **само** полетата и опциите от `forms.json`; всичко друго се отхвърля. Скрито поле и
минимум 3 секунди спират ботовете (отговарят „добре“, нищо не се записва). IP адреси не се пазят.
В CSV клетките, започващи с `=`, `+`, `-`, `@`, се обезвреждат за Excel.

## Качване на споделен хостинг (cPanel)

1. **Първо** се чете `.htaccess` в `public_html` — подпапката наследява правилата му (пренасочвания, кеш).
2. Съдържанието на `ИЗХОД/` отива в подпапката на събитието, например `public_html/<адрес>/`.
3. Празна MySQL база и потребител от cPanel. Таблицата се създава сама при първия отговор.
4. `php/config.example.php` → **извън** `public_html`: `~/.organizer/<slug>.php` (или пътят от
   `ORGANIZER_CONFIG`). Паролата се въвежда там, на сървъра — никога в репото и в публичната папка.
5. `export/` се заключва от cPanel → Directory Privacy. Без това износът отговаря 403.
6. „go“: `publish.indexable: true` (и `publish.base_url` за sitemap.xml) → ново сглобяване → качване.
