# leak-filter — провери за изтичане, преди да е станало публично

## Какво иска
- `ПАПКА` — по подразбиране текущата
- `--words ФАЙЛ` — по желание: думи за търсене (имена на машини, хора, вътрешни домейни), по една на ред,
  `#` за коментар. Файлът стои **извън** репото — иначе сам е изтичане (помощникът предупреждава).
- `--no-history` — само текущите файлове
- `--json` — изход като JSON

## Какво връща
По ред на находка: `файл:ред  вид  намерено` — за историята и commit-а, в който е влязло. Накрая `ЧИСТО.`
или `НАМЕРЕНО: N в папката, M в историята.` Ключовете и токените се показват само с първите 4 знака.

Видове: `ip` (без 192.0.2.x, 198.51.100.x, 203.0.113.x, 127.x), `home-path` (`/home/<име>`, `/Users/<име>`,
`C:\Users\<име>`; без заместители като `user`), `private-key`, `aws-key`, `github-token`, `slack-token`,
`anthropic-key`, `openai-key`, `google-key`, `jwt`, `url-password`, `assigned-secret` (`password = "…"`), `word`.

Историята: всички добавени редове от `git log --all -p`. Изтритото в по-нов commit остава в историята —
ако е качено, е публично. Ред с `leak-filter: ignore` се пропуска (за нарочни примери).

Код на изход: 0 — чисто · 4 — има находки · 2 — грешни аргументи.

## Ниво
чете — нищо не променя, не пренаписва история, не трие. Поправката е решение на човек.

## Къде тече
Навсякъде с Python 3 и git. Без мрежа, без зависимости.

## Пример
```bash
bin/shinkansen run leak-filter . --words ~/.config/shinkansen/leak-words.txt
# config/site.json:12  ip              10.0…******
# docs/notes.md:4      word            example-host  (история, commit 1a2b3c4d5e6f)
# НАМЕРЕНО: 1 в папката, 1 в историята. Нищо не е поправено.
```
